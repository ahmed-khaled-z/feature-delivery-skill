# Repository-driven UI delivery gate

Use this reference only when the canonical specification changes user-facing UI/UX and repository policy makes a UI gate relevant. The repository defines the authoritative design, instructions, skills, assets, commands, approvals, and verification expectations; do not invent a replacement workflow.

Load only the repository-required design/UI skill or instructions. Obtain required shape approval before mutation unless an approved shape already exists. Put measurable layout, spacing, typography, color, responsive behavior, RTL/LTR behavior, accessibility, interaction, loading, empty, error, and permission states in bounded component briefs. Add required assets to the repository first and cite their exact paths.

Verify the repository-required viewport sizes, states, real flows, keyboard access, and RTL/LTR behavior as applicable. If the trigger is absent, record `UI gate: not applicable` without loading this reference or adding UI process.
